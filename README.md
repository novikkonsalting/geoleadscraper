# GeoLeadScraper — Yandex Maps AUTO + BATCH (v1.10.3)

Сбор справочника организаций ЮЗАО Москвы по схеме **COLLECT RAW → LOCAL FILTER → FINAL**.

Google Maps и 2GIS части проекта не затрагиваются: они целиком находятся в
`vendor/mapscan-content.iife.js` и собираются в артефакт без изменений.

## Структура

| `src/shared-entities.js` | Разбор организаций из JSON, который Яндекс Карты загрузили для себя. |

## Сборка и проверка

```bash
node tools/build.mjs --zip     # собрать extension/ и ZIP расширения
node tools/build.mjs --project-zip  # ZIP всего проекта (в git не хранится)
node tools/smoke-test.mjs      # обязательный прогон перед коммитом
node tools/geo-check.mjs       # качество встроенных границ
node tools/analyze-raw.mjs geoleadscraper-yandex_maps-RAW_ALL-*.csv
node tools/bench-store.mjs 4000   # во что обходится запись датасета
node tools/browser-check.mjs      # перехватчик ответов в настоящем Chromium
node tools/extension-check.mjs    # расширение целиком в настоящем Chromium
```

Перед первым прогоном тестов: `npm install` (единственная зависимость —
`fake-indexeddb`, только для тестов; в расширение ничего не попадает).

`tools/build.mjs` — единственный способ получить `extension/content/index.iife.js`
и `extension/service-worker.js`. Правки прямо в `extension/` будут затёрты
следующей сборкой.

## Где лежат данные

Собранный реестр хранится в IndexedDB базы `geoleadscraper`, принадлежащей
**расширению**, а не сайту. Очистка данных yandex.ru его не трогает. В
`chrome.storage.local` остаётся только управляющее состояние: статус, очередь
запросов и счётчики.

Единственное действие, которое удаляет собранные данные, — кнопка
`RESET BATCH — УДАЛИТЬ RAW (N)`. `IMPORT RAW CSV` заменяет реестр импортируемым
файлом. Данные из версий 1.4.x переносятся в IndexedDB автоматически при первом
запуске.

## Порядок работы в Chrome

1. Открыть Яндекс Карты, загрузить CSV с запросами кнопкой
   **ЗАГРУЗИТЬ CSV СО СПИСКОМ ЗАПРОСОВ**. Для полного ЮЗАО лучше брать файлы из
   `data/queries/` по одному району за раз: 132 запроса в одной вкладке — это
   10–20 часов, а RAW накапливается в хранилище между запусками, поэтому
   результат получается тот же.
2. **START RAW BATCH** — сбор идёт без гео- и категорийной фильтрации.
3. **EXPORT RAW** сразу после завершения. Файл называется `RAW_ALL`, если сбор
   прошёл полностью, и `RAW_PARTIAL`, если хотя бы один запрос завершился
   подозрительно рано.
4. **FILTER RAW → FINAL**.
5. **EXPORT FINAL** — принятые организации, **EXPORT REJECTED** — отбракованные
   с колонкой `exclude_reason`.

Фильтрация делает всё сама: классифицирует реестр, догружает карточки тем
организациям, у которых в выдаче не хватило телефона, сайта, часов работы или
категории, и пересчитывает результат. На реальной выдаче из 121 ресторана это
5 запросов к Яндексу, остальные 116 строк карточки не требуют.

Пока идёт фильтрация, доступна кнопка **ОСТАНОВИТЬ ФИЛЬТРАЦИЮ**. Остановка
ничего не теряет: очередь на догрузку живёт в хранилище, и следующий запуск
продолжит с того же места.

RAW можно вернуть в расширение кнопкой **IMPORT RAW CSV** и перефильтровать
сколько угодно раз — повторный сбор Яндекса не нужен.

## Область поиска

Каждый запрос открывается с картой, наведённой на свой район: центр и масштаб
берутся из встроенных границ. Для Яндекса область карты — часть запроса, и без
этого каждый следующий район искался бы с видом, оставшимся от предыдущего.

**Не нажимайте RESET BATCH между районами.** Загрузка следующего CSV с
запросами и START RAW BATCH реестр не трогают — районы копятся в одном
хранилище. `IMPORT RAW CSV` тоже добавляет к реестру, а не замещает его, так что
ранее выгруженные районы можно вернуть обратно. Удаляет данные только
**RESET BATCH**.

На реальных данных Коньково (1174) и Академический (2373) дают вместе 2631
организацию: 916 попали в выдачу обоих районов, и при накоплении второй раз их
собирать не нужно.

## Откуда берутся данные

Сбор читает то, что Яндекс Карты уже загрузили для себя: `state-view` страницы
поиска и JSON, который SPA грузит при прокрутке. Карточка организации
запрашивается только там, где данных из выдачи не хватило, — и только во время
шага **ДОЗАГРУЗИТЬ**.

Колонка `detail_level` в экспорте RAW говорит, как получена строка: `CARD`
(карточка загружена), `LIST` (взято из выдачи), `LIST_ONLY` (карточку загрузить
не удалось). Карточка запрашивается только на шаге фильтрации и только для тех
строк, где чего-то не хватает.

Если Яндекс изменит формат, быстрый путь просто перестанет находить записи и
сбор пойдёт прежним путём — через карточки. Счётчик `Из выдачи без запроса` в
панели показывает, работает ли быстрый путь.

## Категории

Одиннадцать категорий в файле запросов — способ найти организации, а не
классификация. Организация принимается, если её собственная категория в Яндексе
относит её к группе запроса («Общепит» или «Продуктовая розница»), даже если
подкатегория другая: Магнит останется супермаркетом, даже если его нашёл запрос
про специализированную розницу.

В FINAL это видно по колонкам `category_validation` (`MATCH` — совпала
подкатегория, `GROUP_MATCH` — только группа) и `detected_category_group`.

## Район определяется картой, а не запросом

Район, под которым организация попадает в реестр, берётся из её координат
(point-in-polygon по встроенным границам). Запрос — способ найти организацию, а
не утверждение о том, где она стоит: «кафе Черёмушки Москва» находит кафе и в
Котловке, и в Обручевском.

* координаты внутри района запроса → `district_validation = MATCH`;
* координаты в другом районе ЮЗАО → `REASSIGNED`, строка попадает в реестр под
  тем районом, где она на самом деле стоит;
* координаты вне ЮЗАО → единственное географическое основание для отбраковки,
  `exclude_reason = OUTSIDE_UZAO`.

Колонка `detected_district` всегда говорит, где организация находится;
`matched_source_district` — каким районом её нашли. Это разные вещи, и они
хранятся отдельно.

Организация без рубрик принимается как `ACCEPTED_UNVERIFIED` и ставится в
очередь на догрузку карточки: отсутствие данных — не повод её потерять.

## Полнота выдачи

Запрос, давший меньше 15 организаций, помечается как короткий независимо от
того, прокручивался список или нет, и перед завершением сбор трижды пытается
дожать выдачу: переискивает контейнер списка, бросает его в самый низ и
нажимает «показать ещё», если Яндекс её показывает.

Учёт ведётся по всему реестру, а не по загруженному сейчас списку запросов,
поэтому `export_queries_total` и `export_queries_low_yield` в выгрузке из
двенадцати районов описывают все двенадцать. Если короткие запросы есть, файл
называется `RAW_PARTIAL`, а `export_batch_status` — `COMPLETED_WITH_WARNINGS`.

## Сетевые организации и дубли

FINAL несёт `chain_flag` и `chain_size`: сколько строк делят один телефон или
одно название. Строки не удаляются — филиал это реальный адрес, — но рассылка
видит, что 39 из них отвечают на одном коммутаторе. `coord_duplicates`
показывает дубли карточек самого Яндекса — строки с тем же названием в той же
точке с точностью до ≈10 метров. Дедуп при этом остаётся
строго по `place_id`.

Добавочный номер отделён от номера: `phone` и `phone_ext`.

## Что происходит при сбое страницы

Вкладка Яндекс Карт за долгий прогон может уйти в белый экран — рендерер Chrome
исчерпывает память. Пока батч собирает, вкладка раз в 15 секунд отправляет
heartbeat в service worker; замолчавшая на две минуты вкладка перезагружается, и
контент-скрипт продолжает очередь сам. Между перезагрузками одной вкладки не
меньше трёх минут, не больше 40 за прогон.

Вкладка в статусе `USER ACTION REQUIRED` не перезагружается никогда: проверка
Яндекса адресована человеку, и сбор ждёт человека.

После любой перезагрузки — своей или ручной — сбор продолжает текущий запрос с
того места, где остановился. Нажимать PAUSE и RESUME не нужно.

## Границы районов

Границы 12 районов ЮЗАО встроены в расширение и работают из коробки — загружать
ничего не нужно. Источник — OpenStreetMap (`admin_level=8`), © OpenStreetMap
contributors, ODbL 1.0. Геофильтр работает только офлайн.

Подробности и порядок замены границ — в
[`docs/GEO_BOUNDARIES.md`](docs/GEO_BOUNDARIES.md).

## Ограничения по назначению

Расширение не обходит CAPTCHA и access check. Если Яндекс требует действия
пользователя, сбор встаёт в статус `USER ACTION REQUIRED` и ждёт человека.
