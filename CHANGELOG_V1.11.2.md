# v1.11.2 — два CSV перестали путаться

## Что произошло

`IMPORT RAW CSV` получил файл `04_konkovo.csv` — список запросов — и ответил:

```
Это не RAW CSV GeoLeadScraper: не найдены place_id/maps_url/title.
```

Формально верно, по делу бесполезно: не сказано, что это за файл и какой
кнопкой его грузить. Две кнопки стоят рядом, оба файла — CSV, перепутать их
легко. Это недоработка интерфейса, а не ошибка пользователя.

Хуже была обратная ошибка. В выгрузке RAW есть колонка `source_query`, а она
входит в список синонимов для `query`, поэтому **выгрузка RAW принималась как
список запросов** и превращалась в очередь из тысяч «запросов». Молча.

## Исправлено

* Каждый загрузчик узнаёт чужой файл и называет нужную кнопку:
  * список запросов в IMPORT RAW → «Это список запросов, а не выгрузка RAW.
    Загрузите его кнопкой ЗАГРУЗИТЬ CSV СО СПИСКОМ ЗАПРОСОВ»;
  * выгрузка RAW в загрузчик запросов → «Это выгрузка RAW, а не список
    запросов. Загрузите её кнопкой IMPORT RAW CSV».
* Кнопка называется `IMPORT RAW CSV — ДОБАВИТЬ ВЫГРУЗКУ EXPORT RAW`, вторая —
  `ЗАГРУЗИТЬ CSV СО СПИСКОМ ЗАПРОСОВ`.
* **Отклонённый файл больше не переводит BATCH в состояние «Ошибка».** Ничего
  не прочитано, реестр не тронут — сообщение выводится в строке ошибки, статус
  остаётся прежним. На скриншоте статус был «Ошибка» при целых 2100 строках.
* В сообщении теперь есть имя файла.

## Наведение карты работает

На том же районе, до и после:

```
Коньково, v1.10.x:  RAW 1174 -> FINAL  96
Коньково, v1.11.0:  RAW 2100 -> FINAL 285
```

Втрое больше организаций в самом районе. Доля отсева по району осталась
высокой (1815 из 2100), но это уже не потерянная работа: соседние районы
копятся в том же хранилище и пригодятся, когда дойдёт их очередь.
