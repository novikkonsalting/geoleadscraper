# Границы районов ЮЗАО

## Коротко

Границы **встроены в расширение** и работают из коробки. Загружать GeoJSON не
нужно — кнопка осталась только на случай, если вы захотите подставить свой
набор границ.

Источник: OpenStreetMap, `admin_level=8` (районы Москвы), через репозиторий
[timurkanaz/Russia_geojson_OSM](https://github.com/timurkanaz/Russia_geojson_OSM).
Файл `data/uzao_districts.geojson` в этом репозитории — извлечённые 12 районов
ЮЗАО. Константа `LOCAL_GEO` в коде генерируется из него командой
`node tools/embed-boundaries.mjs`, то есть цифры в коде не набраны руками.

**© OpenStreetMap contributors, ODbL 1.0.** Геометрия предназначена для
классификации «точка → район», а не для картографического или юридического
отображения границ.

Система координат EPSG:4326, порядок `[longitude, latitude]`.

## Проверка

`node tools/geo-check.mjs` на встроенном наборе:

```
== regression probes ==
PASS = Академический      -> [Академический]   контрольная точка проекта
PASS ≠ Академический      -> [Коньково]        ложное попадание v1.3.2
PASS ≠ Академический      -> [Тёплый Стан]     ложное попадание v1.3.2
PASS = Академический      -> [Академический]   Штолле, Профсоюзная ул., 4
PASS = Академический      -> [Академический]   Ривьера, просп. 60-летия Октября, 8А
PASS = Академический      -> [Академический]   Гамбринус, ул. Кржижановского, 15к3
PASS = Академический      -> [Академический]   Jolly leprechaun, просп. 60-летия Октября, 20

claimed cells: 3961, claimed by 2+ districts: 0 (0.0%)
ВСЕГО 111.08 km² против ≈111.3 km² у ЮЗАО (расхождение 0.2%)
```

Три критерия, которые не зависят ни от чьей памяти:

1. **Контрольные точки.** Три из них дал владелец проекта по реальным ошибкам
   v1.3.2, четыре — организации из настоящей выдачи Яндекса, стоящие на улицах,
   которые однозначно принадлежат Академическому району.
2. **Топология.** Ни один квадратный метр не принадлежит двум районам
   одновременно. У прежнего набора таких мест было 12% площади округа.
3. **Площадь.** Сумма 12 районов — 111.08 км² против общеизвестных ≈111.3 км² у
   ЮЗАО. Расхождение 0.2% означает, что геометрия покрывает округ целиком и без
   наложений.

## Что было раньше

До v1.7.0 в расширение были встроены упрощённые контуры, нарисованные от руки.
Измерено на них: 12% площади округа принадлежало больше чем одному району,
контур Ясенева лежал поверх Коньково примерно на 10 км², а точка в районе
м. Новоясеневская не попадала ни в один район. Эти контуры удалены.

## Если нужен свой набор границ

Кнопка **ЗАГРУЗИТЬ GeoJSON ГРАНИЦ С ДИСКА** в панели BATCH. Файл читается с
диска, никакой сети во время работы не используется, набор сохраняется в
`chrome.storage.local` и после этого используется вместо встроенного. Кнопка
**ВЕРНУТЬ ВСТРОЕННЫЕ ГРАНИЦЫ** возвращает всё назад.

Требования к файлу: `FeatureCollection`, у каждого района `Polygon` или
`MultiPolygon` и имя в одном из свойств `NAME`, `name`, `name:ru`, `district` —
в том же виде, в каком район назван в очереди запросов. Подойдёт, например,
`data/uzao_districts.geojson` из этого репозитория.

Проверьте файл перед загрузкой:

```bash
node tools/geo-check.mjs путь/к/boundaries.geojson
```

Расширение при импорте дополнительно проверяет, что найдены все 12 районов, что
каждая геометрия похожа на московский район по размеру и положению, и что
проходят контрольные точки. Не прошедший проверку файл не сохраняется, и
активный набор границ не меняется.

## Что делает фильтр при неоднозначности

У встроенного набора перекрытий нет, но импортированный может их иметь —
организация при этом не теряется:

| Ситуация | `district_quality` | Результат |
|---|---|---|
| Точка ровно в одном районе | `EXACT` | обычная классификация |
| Точка в нескольких районах | `AMBIGUOUS` | выбирается район, вглубь которого точка ушла дальше; кандидаты пишутся в `district_candidates` |
| Точка вне всех контуров | `OUTSIDE` | `detected_district = Вне ЮЗАО` |
| Нет координат | `NO_COORDINATES` | отдельная причина отсева, не «не тот район» |
| В запросе нет района | `NOT_CHECKED` | `district_validation = UNKNOWN` |

`source_district` остаётся районом поискового запроса и никогда не используется
как подтверждение фактического района.
