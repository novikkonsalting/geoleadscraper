# v1.11.0 — поиск наводится на тот район, который ищет

## Вопрос

«Почему мы собираем 1174, чтобы потом отфильтровать 1078?»

Потому что карта смотрела не туда. На скриншоте прогона по Коньково адрес
страницы был:

```
?ll=37.577063,55.689009&z=13
```

Это центр **Академического** района. Коньково — 37.531, 55.640, в шести
километрах. `buildSearchUrl` сохранял `ll` и `z` от предыдущей страницы,
поэтому каждый район после первого искался с картой, наведённой на предыдущий.

Для Яндекса область карты — часть запроса: он ранжирует и ограничивает выдачу
вокруг неё. Отсюда и результат.

## Что дала эта ошибка на ваших данных

```
собрано 1174, фактическое расположение:
   707  вне ЮЗАО        (60%)
    96  Коньково        ( 8%)
   371  другие районы ЮЗАО
медиана расстояния от центра Коньково — 6.8 км, максимум 12 км
```

Шестьдесят процентов работы ушло за пределы округа. И, что важнее, в самом
Коньково нашлось всего 96 организаций — против 248 в Академическом, районе
меньшего размера. Похоже, целевой район был недособран.

## Исправлено

Каждый запрос теперь открывается с картой, наведённой на свой район: центр
берётся из встроенных границ, масштаб подбирается так, чтобы район занимал
вид целиком.

| район | центр | z |
|---|---|---|
| Академический | 37.5769, 55.6895 | 13 |
| Коньково | 37.5313, 55.6405 | 13 |
| Ломоносовский | 37.5336, 55.6791 | 14 |
| Южное Бутово | 37.5397, 55.5259 | 12 |
| Ясенево | 37.5372, 55.6156 | 12 |

Запрос без района (одиночный поиск) ведёт себя как раньше и вид не трогает.

Насколько это уменьшит долю чужих результатов, покажет первый прогон: проверить
это из среды разработки нельзя, доступа к Яндекс Картам отсюда нет. Ожидание —
и меньше мусора, и **больше найденных в самом районе**, потому что выдача
перестанет быть размазанной по соседнему округу.

## Не сбрасывайте RAW между районами

Из 1078 отсеянных 371 находятся в других районах ЮЗАО. Если хранилище копится,
они пригодятся, когда дойдёт очередь до их районов, — дедуп по `place_id`
сведёт повторы, и собирать их второй раз не придётся. Кнопка
**RESET BATCH — УДАЛИТЬ RAW** стирает именно это накопление.

Судя по числам (1174 после Коньково против 2373 после Академического),
хранилище между районами обнулялось.
