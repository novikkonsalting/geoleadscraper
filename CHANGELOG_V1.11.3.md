# v1.11.3 — при слиянии пустое поле больше не побеждает заполненное

## Баг

При объединении выгрузок четырёх районов в реестре недосчитались организаций:
Гагаринский дал 113 строк вместо 124, которые тот же прогон дал сам по себе.

Пропали «Пятёрочка», «Магнит», «Азбука вкуса», «Дикси», «ВкусВилл», «Гудман»,
«Вкусно — и точка» и другие. Все одинаково: в файле Академического они пришли
**тонкой строкой из выдачи, без категорий**, а в файле Гагаринского — полной,
с категориями и телефоном.

`mergeRecord` держал правило «побеждает первая версия карточки». Правило нужное:
оно не даёт повторному тонкому чтению затереть уже загруженную карточку. Но
пустое поле — не версия, а дыра, и первая версия сохраняла дыру навсегда.

## Исправлено

Заполненное значение из пришедшей строки заполняет пустое в сохранённой.
Непустое сохранённое по-прежнему не затирается — тонкое чтение ничего не
испортит. `detail_level` повышается до лучшего известного: `LIST` → `LIST_ONLY`
→ `CARD`.

Провенанс по-прежнему объединяется, а не замещается.

На четырёх районах:

```
было:  FINAL 540  (Академический 244, Гагаринский 113, Зюзино 89, Коньково 94)
стало: FINAL 555  (Академический 247, Гагаринский 122, Зюзино 92, Коньково 94)
```

## Объединение четырёх районов

```
в файлах суммарно  7464 строки
в реестре          4121 организация
пересечений        3343
```

Каждый следующий район добавляет всё меньше нового: 2373 → 1235 → 385 → 128.
Это и есть причина не сбрасывать реестр между районами.
